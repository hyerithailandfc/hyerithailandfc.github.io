# AI workflow — how Claude handles admin requests

Requests arrive as GitHub issues labeled `claude-request`, created by the Admin page (`admin/`).
The issue body starts with `**Type:** <type>`. Follow-up instructions come as comments starting with `@claude`.
Always work on branch `claude/issue-<n>`, open/update one PR, and reply on the issue **in Thai**.

## Type: `refresh-data` (update from namu.wiki)
The issue contains `**Section:**`, `**namu.wiki last modified:**` and pasted Korean (or English) source text.
1. Compare the pasted text with the matching data file(s) (see content-guide.md schemas). Identify only what's **new or changed**.
2. Update the JSON — add new works/awards in chronological position, fix changed facts. Don't delete existing entries unless the
   source clearly shows they're wrong; mention any removal in the PR.
3. Write all three languages per content-guide.md. If a new show/award adds a new `kind`/`type`, add UI strings for it.
4. If the change is a career milestone (new lead role, major award, new regular show), also add or extend a `journey.json` item.
5. Update `site.json → source.sourceLastModified` and `source.lastSynced`.
   When the request comes from the "TMDB credit not on the site" button, add `"tmdbId"` to the new works entry.
   Never edit `data/tmdb.json` / `data/youtube.json` by hand — they are regenerated by the sync workflow.
6. In the issue comment, list every added/changed fact as bullet points so the admin can verify quickly.

## Type: `new-page`
1. Create `assets/js/pages/<id>.js` following the **page module contract** below.
2. Put its content in a new `data/<id>.json` (localized) — never hard-code content in JS.
3. Register it in `data/site.json → pages` (`id`, `path`, `module`, `label {th,en,ko}`; `nav: false` if it shouldn't be in the menu).
   Keep the menu short: if there are more than ~8 nav items, ask the admin which to hide.
4. Add UI strings to all three `data/i18n/*.json` files under a new top-level key named after the page id.
5. Reuse components from design-system.md; add CSS to `main.css` under a clearly commented section only if needed.
6. If useful, link to the page from an existing page (e.g. a button on Home).

## Type: `feature` / `design`
Change the smallest set of files. For design changes, update tokens or components in `main.css` **and** document the change in
design-system.md (and decisions.md if it changes the theme direction). Check both light and dark mode.

## Type: `bug`
Reproduce by reading the code path, fix the root cause, mention the cause in the PR.

## Type: `other`
Interpret sensibly within the hard rules; if it needs a decision from the admin, ask in the issue before building.

## Page module contract
```js
import { loadJSON, tx, ui, esc, icon } from '../core.js';

export async function render(ctx) {      // required — returns an HTML string
  const data = await loadJSON('data/<id>.json');
  return `
  <section class="page-hero"><div class="container">
    <span class="eyebrow reveal">${icon('star')} Label</span>
    <h1 class="reveal"><span class="title-pop">${esc(ui('<id>.title'))}</span></h1>
    <p class="reveal">${esc(ui('<id>.sub'))}</p>
  </div></section>
  <section class="section" style="padding-top:12px"><div class="container">…</div></section>`;
}
export function mount(root, ctx) {}       // optional — attach listeners, countUp(root), etc.
export function unmount() {}              // optional — clean up global listeners/overlays
```
- `render` is called again on language change, so don't cache translated strings in module scope.
- Only use `t()/tx()/ui()` for text; only `esc()`-ed values in HTML.
- Update in-page state (tabs, filters) without re-routing; use `setRouteQuery()` to keep it shareable.

## Before you push
- `node tools/validate.mjs` passes.
- Mentally (or with a headless browser if available) check 360px / 1280px and all three languages.
- Add a `docs/changelog.md` entry: `## YYYY-MM-DD — #<issue> <title>` + 1–4 bullets.
